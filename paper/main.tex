\begin{abstract}
Our results distinguish accuracy by answer position and competing text retained during selection more clearly than by prompt length. We evaluate the frozen \modelName{} artifact on \sampleSize{} deterministic probes that ask the model to retrieve clauses from synthetic contracts with mean prompt lengths of \tierTwoTokens{}, \tierFourTokens{}, and \tierEightTokens{} tokens. Accuracy was higher with the answer clause at the end than at the start by \positionTwoStartEndChange{} points at the shortest tier and \positionFourStartEndChange{} points at the middle tier. Keyword pruning reduced accuracy from \pruningFullAccuracy{}\% to \pruningPrunedAccuracy{}\% because it retained a clause whose wording matched the question but whose code was wrong. A query-entity selector excluded that lexical decoy and reached \entitySelectorAccuracy{}\% accuracy on the same \entitySelectorCount{} cases. The matched comparison across prompt lengths remained inconclusive. The practical finding is therefore narrower: test a cheap selector against plausible lexical competitors before using it to shorten documents for this model.
\end{abstract}

\section{Introduction}

You paste a long contract into a chatbot and ask, ``What code renews the vendor agreement?'' The answer sits in one clause, but a similar buyer clause repeats the words in your question and gives a different code.

This ordinary lookup becomes less predictable when the prompt contains a long document. The model may fail because it must process more text, because the answer appears in a weak position, or because nearby text resembles the question. Testing these explanations requires different comparisons: match the scenarios across document lengths, move the key clause within the same document, and inspect the text retained by a filter. In each comparison, the scenario content must remain fixed.

We study these explanations with a synthetic, gradeable version of the contract situation. Each document contains an answer-bearing vendor clause and a similar-looking clause for another company. The question uses the wording of the similar-looking clause, while the answer clause expresses the same relation in different words. This construction reduces the value of literal matching, following the motivation of NoLiMa \citep{modarressi2025nolima}.

We evaluate a frozen open model at laptop scale using paired comparisons. Prior work established position and length failures in larger systems \citep{liu2023lost,levy2024same} and showed that irrelevant statements can disrupt reasoning \citep{shi2023distracted}. Our main comparison moves the same answer clause while preserving the question, clause wording, codes, and filler order. We then compare a deterministic keyword filter with a query-entity selector that keeps sentences naming the company in the question. This comparison tests whether shortening helps when a selector retains or excludes the clause whose wording matches the question.

The experiment asks three questions:
\begin{enumerate}
    \item How does moving the same answer clause among the start, middle, and end change accuracy?
    \item How much accuracy do keyword overlap and query-entity selection preserve on the same cases, and which clauses do they retain?
    \item As mean prompt length grows from \tierTwoTokens{} to \tierEightTokens{} tokens, how much does accuracy change on shared cases?
\end{enumerate}

Within this grid, accuracy was higher when the answer appeared near the end. This position result is diagnostic rather than directly deployable because using it requires knowing the answer location. By contrast, the deployable query-entity selector avoided the lexical trap amplified by keyword pruning. The matched comparison across prompt lengths did not identify a degradation threshold.

\section{Related Work}

\citet{liu2023lost} found a U-shaped position curve in multi-document question answering and key-value retrieval, with stronger use of information near context boundaries. We conduct a smaller clause-reordering test that holds the question, filler sequence, clauses, codes, and the competing clause's final sentence index fixed while placing the answer clause at a different depth. The observed pattern mainly favors recent information rather than forming a full U-shape because accuracy is also low when the answer appears at the start.

Prompt length can matter even when the underlying problem is fixed. \citet{levy2024same} padded matched reasoning problems and observed degradation well before the models reached their context limits. RULER likewise found that usable context lengths can be shorter than advertised windows \citep{hsieh2024ruler}. Our comparison includes only cases present at every prompt-length tier, keeping the mix of scenarios fixed as the documents grow.

\citet{shi2023distracted} added irrelevant statements to arithmetic problems and found lower reasoning accuracy. Our filler bundles vary several properties together, so we balance them within the main comparisons but do not claim an isolated relevance effect. NoLiMa shows that synthetic retrieval tests based on literal word matches can overstate retrieval ability \citep{modarressi2025nolima}. We therefore express the question and answer clause in different words while giving the competing clause the same surface wording as the question. The tested model belongs to the instruction-tuned Qwen family \citep{qwen2024qwen25}.

\section{Probe Design}

\paragraph{Model and execution.}

We run the model through \texttt{llama-completion} with greedy decoding, zero temperature, and a fixed seed. The complete manifest contains \manifestProbeCount{} probes, each stored as one prompt and one raw output. On a rerun, the program skips existing outputs and resumes interrupted inference using each probe's stable identifier.

\paragraph{Scenario families.}
For each scenario family, seeded code generates a target company and code, a competing company and code, a question, and filler text. The question asks for the renewal code needed to extend the target company's contract. Its wording exactly matches the competing clause, whereas the answer-bearing clause calls the same value a renewal identifier. A matched literal control reverses the wording of the two clauses while retaining the same filler.

For each family evaluated with the full document, we place the answer clause near the start, middle, or end. The random seeds used to generate a family do not depend on the answer position. Before filling the document, we assign final sentence slots to the answer and competing clauses. The competing clause keeps the same final sentence index across all three versions, while the answer moves and the remaining filler sentences preserve their order. Each paired position contrast therefore changes only the answer placement.

\paragraph{Amount and filler control.}
The tokenizer, rather than a character estimate, determines prompt length. The three tiers evaluated with the full document average \tierTwoTokens{}, \tierFourTokens{}, and \tierEightTokens{} tokens. Each tier balances business filler with unrelated sentences. Business filler consists of other companies, records, and unrelated codes; unrelated filler describes places and events outside the contract domain. Each pair of filler conditions shares the scenario family, answer position, question, and tokenizer-measured length tier.

The two filler conditions differ in several ways. Compared with unrelated prose, the related filler contains more business entities, contract-like templates, and code-shaped answer candidates. Their paired contrast therefore measures the difference between these generated conditions, not an isolated effect of topical relevance.

The final tier contains fewer families because running longer prompts is more expensive. Estimates across prompt lengths therefore use only the \amountSharedEightCount{} cases shared by every tier rather than the unequal totals from the full tiers. We balance both filler bundles within each reported comparison of answer position and prompt length but do not interpret the contrast between bundles as a context-quality effect.

\paragraph{Selectors and controls.}
At the middle prompt-length tier, a keyword filter retains sentences that share at least two content words with the question. If too few sentences qualify, the filter instead keeps those with the highest overlap. A second selector extracts the company named after ``contract with'' in the question and keeps sentences containing that name. If extraction or matching fails, this selector falls back to the keyword filter. Both rules use only visible text, preserve the original sentence order, and require no answer labels. We restrict the comparisons to the \pruningDenominator{} cases available with the full document and with both selector outputs. We also include \closedBookCount{} questions asked without a document and \literalControlDenominator{} matched controls that compare literal with paraphrased wording.

The keyword filter retained the answer clause and lexical decoy in all \pruningPrunedCount{} matched prompts. The query-entity selector retained the answer clause in \entitySelectorTargetRetainedCount{} prompts and the decoy in \entitySelectorDistractorRetainedCount{}. A paired diagnostic removes only the decoy from each keyword-pruned prompt, leaving every other selected sentence fixed. This diagnostic uses the known synthetic label; both automatic selectors do not.

\section{Scoring and Comparisons}

Before scoring, we remove only the fixed transport text appended by the runner. A response then counts as accurate only if it contains the target code without the competing code. It complies with the exact-output instruction if it contains one code and no other text. We classify a response as a distractor capture when it contains the competing code without the target; a response is invalid when it contains both expected codes or neither.

We report descriptive results for the observed scenario families generated from fixed seeds. Each accuracy appears with its probe and family counts. Paired changes use only scenarios present in both conditions and include wins, losses, and ties. A win is a case corrected by the second condition, while a loss is a case that becomes incorrect. The grid contains only \tierEightFamilyCount{} to \tierTwoFamilyCount{} families per tier evaluated with the full document, which does not support a population confidence claim. Because greedy decoding is deterministic, repeating it adds no sampling uncertainty.

\section{Limitations}

The findings concern one small quantized model and may not transfer to larger models or other quantization levels. Synthetic clause lookup is not natural contract analysis, and retrieval accuracy is not a measure of general capability. The \cpuBudgetMinutes{}-minute CPU budget capped the grid, leaving only \tierEightCount{} probes evaluated with the full document at the longest tier and few families throughout. These estimates describe the observed families rather than a broader population from the generator. Because the longest tier is sparse, we cannot draw a conclusion about degradation within the measured range or address longer prompts. The filler comparison confounds topical relation with semantic domain, entity and code density, candidate count, and sentence templates. Identifying an effect of topical relevance would require a factorial design that matches those properties. Greedy decoding removes run-to-run sampling variation but does not show how sampling would change the estimates. Query-entity selection assumes that the question names one company exactly and that the relevant sentence repeats that name. It does not address aliases, pronouns, or queries without a unique named subject. The decoy-removal control also depends on a known answer label unavailable in natural documents.

\section{Reproducibility}

Analysis scripts generate every reported quantity from the committed probe manifest and raw model outputs. This procedure follows the principle that reports of computational evidence should expose their budget and variation \citep{dodge2019show}. The model and cached data are frozen and checksummed, and each raw output retains its stable probe identifier. From the cached outputs, \texttt{make all} regenerates \texttt{results.json}, the LaTeX value macros, and the paper. The command \texttt{make clean-deep \&\& make all} instead repeats deterministic model inference. Repository gates check frozen inputs, citation resolution, number provenance, pipeline freshness, result sanity, prose style, anonymity, and compilation.
